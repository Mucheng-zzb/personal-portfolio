## 一句话结论：

`a = b` 只是给同一个对象贴了两个标签，只有可变对象才会出现“改一个另一个也变”。

## 我遇到的问题

我给列表起了第二个名字，往新名字里加东西，老名字也跟着变。

可我把新名字换成别的列表时，老名字又不动了——到底哪个才算“复制”？

## 我以为对的 / 原来的做法

我原以为 `a = b` 是复制，以为两个变量会“互相改变”，甚至以为数字也会这样。

现在我知道其实是：`=` 只做一件事——让左边的名字指向右边那个东西。它不复制任何东西，也不会把两个名字绑在一起。

## 现在怎么做

**1. 贴标签 vs 造新盒子**

`a = [1,2]` 是造一只新盒子；`b = a` 是给同一只盒子再贴一张标签；`c = list(a)` 才是造一只新盒子。用 `is` 一判就知道是哪一种：

```python
a = [1, 2]
b = a            # 贴标签：两个名字，一只箱子
print(a is b)    # True

c = list(a)      # 造一只新盒子，把内容装进去
print(a is c)    # False
```

```
True
False
```

**2. 改名字 vs 改东西**

这是这篇最关键的一幕：`b.append(3)` 改的是箱子本身，所以 `a` 也跟着变；而 `y = 6` 只是把标签 `y` 挪到别的东西上，`x` 动都不动。

```python
a = [1, 2]
b = a
b.append(3)      # 改箱子本身
print("a =", a)
print("b =", b)

x = 5
y = x
y = 6            # 只是把标签 y 挪到 6 上
print("x =", x, "| y =", y)
```

```
a = [1, 2, 3]
b = [1, 2, 3]
x = 5 | y = 6
```

反过来也能验证：我把标签 `b` 挪到另一只箱子上，`a` 一点都没变——两个名字之间没有任何绑定关系。

```python
a = [1, 2]
b = a
b = [9]          # 把 b 挪到另一只箱子上
print("a =", a)
print("b =", b)
```

```
a = [1, 2]
b = [9]
```

**3. 真要复制，就自己造一只新盒子**

用 `list(c)` 或者 `c.copy()`。判据是 `is` 打印 `False`——那就说明它真的是两个东西。

```python
a = [1, 2]
c = list(a)
c.append(3)
print("a =", a)
print("c =", c)
print(a is c)
```

```
a = [1, 2]
c = [1, 2, 3]
False
```

## 代价与边界

最实用的代价是：把列表传进函数，函数里的 `append` 会静默改掉调用者那只箱子。

```python
def add_item(bag):
    bag.append("apple")

mine = ["pear"]
add_item(mine)
print("mine =", mine)
```

```
mine = ['pear', 'apple']
```

它危险在：不报错、静默改变，容易引发难以追踪的 bug。

另外数字和字符串没有这个现象，很容易只记住一半。

## 一句话总结

变量名只是标签，`=` 是贴标签，不是复印机。
