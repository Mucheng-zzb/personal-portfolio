## 一句话结论：

列表的下标不是“第几个”，而是“**从开头往前走几步**”：第一个元素是 `[0]`，所以 3 个元素的列表最后一个下标是 `2`——写 `[3]` 会当场报错。

## 我遇到的问题

我想拿列表的最后一个元素，顺手就写了 `[3]`——因为列表里明明有 3 个东西。

结果屏幕上不是我要的元素，而是一句报错。

我又试了 `pets[len(pets)]`，还是同一句报错。当时我觉得是“下标坏了”。

## 我以为对的 / 原来的做法

我以为 `pets[3]` 就是“第 3 个元素”。

我以为 `len(pets)` 也能直接拿来当下标——有几个元素，下标不就是几吗？

我还以为越界会给我一个空值，让我自己去判断。

**其实**：这三个想法都不对。下标数的是“**走几步**”，不是“第几个”；而越界不是给空值，是**当场报错**。

## 现在怎么做

**1. 下标是“走几步”**

```python
pets = ["cat", "dog", "fish"]

print(pets[0])    # 走 0 步 → 第一个
print(pets[1])    # 走 1 步 → 第二个
print(pets[2])    # 走 2 步 → 第三个
print(len(pets))  # 3：一共有几个
```

```
cat
dog
fish
3
```

**2. `len` 是“有几个”，最后一个下标是 `len - 1`**

这是最容易差一的地方：`len` 是 3，但最后一个下标是 **2**。

```python
print(pets[len(pets) - 1])   # fish
print(pets[len(pets)])       # 越界
```

```
fish
IndexError: list index out of range
```

`pets[len(pets)]` 恰好越界一个——不多不少。

**3. `-1` 是拿最后一个的捷径**

```python
print(pets[-1])   # fish：从末尾往前 1 步
print(pets[-3])   # cat：往前 3 步，回到第一个
```

```
fish
cat
```

## 代价与边界

越界是**立刻报错**，不是悄悄给我一个空值。这其实是好事：错误当场暴露，不会带着一个“看起来能用”的空值继续往下跑。

想拿最后一个元素，优先写 `-1` 而不是 `len(pets) - 1`——少一处减法，就少一次算错的机会。

负数下标也不是万能的。空列表上取 `[-1]` 照样报错（`len(empty)` 是 0，`empty[-1]` 直接 `IndexError: list index out of range`）；`-4` 这种超出范围的下标，一样会越界。

## 一句话总结

下标回答的是“**走几步**”，不是“**第几个**”——这就是所有差一错误的源头。
