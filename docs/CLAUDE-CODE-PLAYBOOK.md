# 给 Claude Code 的指令手册（v0.2 → v1.0）

> 配套：[ROADMAP.md](./ROADMAP.md)（排期与范围）、[ARCHITECTURE.md](./ARCHITECTURE.md)（架构与接口）
> 用法：每个版本开始时，把本文件对应的**指令块**整段复制给 Claude Code。一次只喂一个指令块。

---

## 0. 怎么用这份文件（30 秒版）

1. 版本开始时，打开对应章节（如 §5.5 v0.5）。
2. **先让 Claude Code 读两份文档**（指令块已内置这一步）。
3. 按顺序执行 A → B → C：**一次一个指令块**，做完一个验收再下一个。
4. 每个指令块结束时，Claude Code 必须给出「变更摘要 / 验证结果 / 未完成项」。**没有验证结果就不算完成。**
5. 版本收尾时，用 §7 的复盘指令生成版本复盘。

**三条铁律**
- **一次只做一件事。** 不要在一个 Prompt 里塞两个版本的工作。
- **每个 Prompt 都带验收标准。** 没有验收标准的任务不要交给 Claude Code。
- **你不懂的代码不要合。** 让 Claude Code 用「给大一学生的解释」讲一遍改动，讲不懂就要求简化。

---

## 1. 总则（每个指令块都默认包含）

Claude Code 在每个任务中必须遵守：

1. **先读后写**：开始前阅读 `docs/ROADMAP.md`、`docs/ARCHITECTURE.md`、`CLAUDE.md`，并说明本次任务属于哪个版本。
2. **只做被要求的事**：不重构无关代码、不顺手升级依赖、不改变既有视觉风格（除非任务明确要求）。
3. **小步提交**：每个逻辑单元一次提交，Conventional Commits + 中文描述。
4. **可验证**：每个任务结束必须运行对应命令（见 §6），并**粘贴真实输出**。禁止写「应该可以了」。
5. **降级优先**：任何外部依赖（API / 数据库 / LLM）都要先想好失效时怎么办。
6. **密钥零容忍**：任何密钥只能来自环境变量；发现硬编码必须立即报告并修复。
7. **同步文档**：改动涉及接口/结构/决策时，同一个 PR 内更新 `docs/` 与 `CHANGELOG.md`。
8. **面向初学者**：关键改动用 3–5 行「人话解释」说明原理，方便我学习。
9. **承认不确定**：不确定就去查证（读代码、跑命令、查官方文档），不要猜。
10. **结束必答**：变更摘要 / 验证命令与结果 / 未完成项与风险 / 下一步建议。

## 2. 仓库根 CLAUDE.md

仓库根已有 `CLAUDE.md`（仓库级约定，每次会话自动生效）——**它是这些约定的唯一事实来源**。

本节**不再复制一份模板**：v0.2-B 时期这里曾内嵌一份 `CLAUDE.md` 的副本，后来与真实的
`CLAUDE.md` 分叉，留下过「唯一工作区是 `v2.1-A/`」这种过期约定（已在 v0.2-B 收尾时修正）。
同一份约定存两处，一定会再次分叉。

维护约定：
1. 要改仓库级约定 → 直接改根目录 `CLAUDE.md`，并在 `docs/HANDOFF.md` 的决策登记表里记一笔；
2. 本手册只写「怎么做」（流程、逐版指令块、禁止清单），不重复「项目约束」；
3. 新增任何约束时，同步更新根目录 `CLAUDE.md`。

### 5.1 v0.2 —— 工程基线 + 内容数据化

**A. 建立工程骨架**
~~~text
【版本】v0.2-A
【背景】仓库现在只有 index.html / style.css / script.js 三个文件，没有构建工具，部署方式是 GitHub Pages 从分支部署。
【目标】建立 monorepo 骨架与 Vite 构建，构建产物为纯静态文件，仍部署到 GitHub Pages 且 URL 不变。
【范围】
1) 新建 web/ 目录，把 index.html、script.js、style.css（及后续拆分的样式）迁入；api/ 目录先放一个占位 README.md 说明用途。
2) 在 web/ 初始化 Vite（vanilla 模板，原生 JS，type=module），package.json 提供 dev / build / preview / check 四个脚本。
3) vite.config.js 中 base 必须设为 '/personal-portfolio/'（仓库名为 personal-portfolio，Pages 地址是子路径）。
4) 保持页面视觉与 v0.1 完全一致——这一步只搬家，不改设计。
5) 更新 .gitignore（node_modules、dist、.env 等）。
6) **过渡状态**：根目录的 index.html / script.js / style.css 作为**临时保活副本**保留（Pages 此时仍从分支根目录部署），真值来源是 web/，根目录三件套不再改功能；待 v0.2-B 切换部署后删除。
【不做】不引入任何 UI 框架；不引入 CSS 预处理器；不改配色、字体、布局；不删除现有功能（滚动淡入/导航高亮/复制邮箱）。
【技术约束】遵循 ADR-002、ADR-009。
【验收标准】
- [ ] npm ci && npm run build 成功，web/dist 下是纯静态文件
- [ ] npm run dev 能在本地打开并看到与线上一致的页面
- [ ] 控制台无报错；复制邮箱按钮仍可用
【验证方式】运行构建命令并粘贴输出；列出 web/dist 的文件清单。
【输出要求】变更摘要 / 验证结果 / 未完成项 / 下一步建议
~~~

**C. 内容层：把硬编码内容抽成数据**
~~~text
【版本】v0.2-C
【目标】新增一个项目或改一段个人信息时，只需要改 web/content/ 下的数据文件，不用碰 HTML。
【范围】
1) 建立 web/content/：profile.json（姓名/定位/邮箱/GitHub/技能/关于我）、projects/*.md（front-matter 见 ARCHITECTURE §5）、now.json。

6) 更新 README：如何新增一个项目、如何改个人信息。
【不做】不改视觉；不加新板块；不引入状态管理；不请求后端 API（那是 v0.5）。
【验收标准】
- [ ] 在 web/content/projects/ 新增一个 .md 文件并重新构建，页面上自动出现新项目卡，全程未改 HTML
- [ ] 故意删掉某个 .md 的 title 字段，构建必须失败并明确报错（验证校验生效）
- [ ] 禁用 JavaScript 后，姓名、定位、邮箱、GitHub 仍然可见
- [ ] 页面与改造前视觉一致（附前后对比说明）
【验证方式】运行构建；执行一次'新增项目'与'字段缺失'两个演练并粘贴结果。
【输出要求】变更摘要 / 验证结果 / 未完成项 / 下一步建议
~~~

~~~text
1) SQLModel（或 SQLAlchemy）+ Alembic；本地 SQLite，线上托管 Postgres，通过 DATABASE_URL 切换。
2) 表结构见 docs/ARCHITECTURE.md §7：guestbook（存 ip_hash，不存明文 IP）。
3) POST /api/v1/guestbook（姓名 ≤30 字、留言 ≤500 字，必填校验）、GET /api/v1/guestbook（limit + cursor 分页）。
4) 限流 3 条/小时/IP；蜜罐字段；纯文本存储（保留换行，禁用 HTML）。
5) DELETE /api/v1/guestbook/{id}，需环境变量中的 Bearer token。
6) 前端留言板 UI：提交中/成功/失败三态，失败回滚乐观更新，错误提示使用后端 message。
7) 数据库不可用时，留言板区域显示'暂时不可用'，不影响其他页面。
【不做】不做注册登录、头像、嵌套回复；不做富文本；不做实时推送。
【验收标准】
- [ ] 提交留言后刷新仍存在（证明落库）
- [ ] 空/超长/含 HTML 的输入被 422 拒绝，前端显示可读提示
- [ ] 第 4 次连续提交返回 429（附 curl 输出）
- [ ] 停掉数据库后，页面其他部分正常，留言板显示占位提示
- [ ] alembic upgrade head 可在空库一键建表
【输出要求】变更摘要 / 验证结果 / 未完成项 / 下一步建议
~~~

## 7. 复盘与求助指令

**版本复盘（每版末用）**
~~~text
现在 v0.X 收尾了。请不要写代码，只做复盘，输出：
1) 本版目标 vs 实际完成（逐条对照 ROADMAP 的验收标准，给出证据）
2) 未完成或降级的部分及原因
3) 我这一版学到的 3 个知识点（用大一学生能懂的话解释，各 3 行以内）
4) 这一版有什么技术债，会在什么时候爆发
5) 下一版开始前，我应该先补的 1 个知识短板
~~~

**周报（每周日）**
~~~text
根据本周的 git log 与改动，帮我写一份 5 行的周报：做了什么 / 卡在哪 / 下周计划。不要写代码。
~~~

**讲解模式（看不懂时用）**
~~~text
用大一学生能听懂的话，解释你刚才这次改动：1) 它解决什么问题 2) 数据怎么流动 3) 哪一行最关键 4) 如果我要改，应该动哪里。不要贴大段代码。
~~~

**降级求助（卡住超过 2 小时时用）**
~~~text
我卡在 <问题> 已经 2 小时。请：1) 用一句话说明最可能的原因 2) 给我一个 10 分钟内能验证的简化版本 3) 如果简化版也不行，告诉我应该接受什么降级方案并记录到 ROADMAP 的砍单记录里。不要继续在复杂方案上投入。
~~~

**回滚（出错时用）**
~~~text
线上出问题了。请：1) 判断影响范围（前端/后端/数据库/AI 分别是否受影响）2) 给出最快回滚到上一个可用版本的具体命令步骤 3) 说明回滚后数据会不会丢 4) 事后写一段事故记录到 docs/INCIDENTS.md。先只给步骤，不要改代码。
~~~

## 8. 禁止清单（Claude Code 不得擅自做）

1. ❌ 引入前端框架（React/Vue/Svelte/Next）或 CSS 框架（Tailwind/Bootstrap）。
2. ❌ 引入向量数据库、消息队列、Redis、Docker Compose 全家桶。
3. ❌ 把任何密钥、token、连接串写进代码或配置文件。
4. ❌ 擅自修改 `web/content/` 下的**内容**（可以改解析逻辑，不可以替我写笔记/项目描述）。
5. ❌ 未经验证就宣称完成，或用「应该」「大概」描述结果。
6. ❌ 顺手重构无关代码、顺手升级依赖、顺手改设计。
7. ❌ 为了跑通而删除测试、加 eslint-disable、吞掉错误（`except: pass`、空 catch）。
8. ❌ 破坏降级路径：任何让前端强依赖后端的改动都必须拒绝。
9. ❌ 引入需要信用卡或有试用期的付费服务。
10. ❌ 在未确认免费额度前就绑定某个 LLM 供应商或数据库供应商。
